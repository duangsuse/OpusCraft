# VoxelCraft 路线图：Minecraft 拥有的一切与我们缺少的一切

对 **Minecraft Java 版 26.3 "Wilderness Bound"**（2026 年 9 月 15 日，最新版本）内容的调研，与 VoxelCraft 现有的内容作比较，并给出分阶段的追赶计划。图例：✅ 已完成 · 🟡 部分完成 · ❌ 缺失。

## 1. 概览

截至第 8.6 阶段结束时的状态（2026-09-27）。统计数字来自 `docs/cobertura.md`，它把 26.3 导出的目录与游戏内的注册表做了交叉比对。

| | Minecraft 26.3 | VoxelCraft 现状 |
| --- | --- | --- |
| 维度 | 3（主世界、下界、末地） | ✅ 全部 3 个 |
| 生物群系 | 67（主世界 53 个、3 个洞穴群系与深暗之域、下界 5 个、末地 5 个以及虚空） | 🟡 63（缺少苍白之园、斑驳森林、硫磺洞穴和虚空） |
| 结构 | 22（另有装饰性要素：晶洞、地牢、化石……） | 🟡 20：主世界 15 个（含要塞）、下界 4 个和末地城（另有 4 个装饰性要素，以及末地黑曜石柱和末地折跃门） |
| 生物 | 86 种生物，含 2 个 Boss | 🟡 73（含末影龙） |
| 方块 | 1,286 | 🟡 约 1,070 |
| 物品 | 1,658 | 🟡 约 1,350（含方块） |
| 配方 | 2,042 | 🟡 1,015（其余配方用到的物品尚不存在） |
| 世界高度 | 384（从 -64 到 320） | ✅ 384（从 -64 到 319）；下界 128 |
| 系统 | 红石、附魔、药水、交易、袭击、进度…… | 🟡 除进度与统计信息、冒险/旁观/极限模式和游戏规则（第 9 阶段）之外全部具备 |

主世界已经完整，只差 2024–2026 年的内容（第 9 阶段）。下界（8.1–8.5）和末地（8.6）已经完整。剩下的就是凋灵（8.7）和第 9 阶段的元游戏。

## 3. 技术要求（关键路径）

几乎所有缺失的内容都依赖这些基础。最好在内容之前完成它们：

1. ✅ **使用 16 位标识符的方块状态。** 现在每个方块占 1 字节（最多 256 种），朝向是单独的标识符。Minecraft 需要按方块存储属性：朝向、上半或下半、开启或关闭、作物生长阶段、红石信号强度、含水……必须把区块改为使用 `Uint16Array` 加状态注册表，并迁移已保存的世界（编辑记录、协议和网格化格式）。
2. ✅ **非立方体方块模型。** 楼梯、台阶、栅栏、墙、门、床、玻璃板、告示牌、墙上的火把、带盖的箱子……需要在网格化中按状态生成模型（带 UV 的箱体），并在物理与射线检测中按状态生成碰撞箱。
3. ✅ **维度。** 每个房间多个世界（主世界、下界、末地），各自有自己的生成器、天空和光照，以及它们之间的传送门。
4. ✅ **结构。** 确定性的构建器，每个区块只绘制属于自己的部分（地表结构用区域网格，矿井用链式部件），以及给它们的箱子用的战利品表，由服务端在第一次生成区块时填充。
5. ✅ **更完整的实体。** 装备、骑乘、驯服、幼崽、投掷物和状态效果，生物用数据定义而不是写死在代码里。
6. ✅ **服务端红石。** 相邻方块更新、计划刻和信号传播，同时注意 Durable Object 的 CPU 开销。
7. **服务端对物品栏和生命值的权威**，如果游戏对陌生人开放的话（现在信任每位玩家的浏览器）。
8. ✅ **仓库内的测试**（服务端与浏览器）和 GitHub Actions 中的自动检查，才能在不破坏已有功能的前提下继续成长。

### 附加 —— 邻近语音聊天 · ✅ 已完成

- ✅ **基础：** 浏览器之间直连的 WebRTC（使用 Cloudflare 和 Google 的 STUN，无中继）；Durable Object 只分配谁在说话，并转发经过校验的信令，且限于同一维度内。按键说话（V，可配置）或开口即开、带灵敏度的麦克风；第一次使用时才会请求麦克风权限。3D 语音（HRTF）从说话者的头部发出，2.5 格内完整，48 格外听不见。自己的麦克风指示灯，说话者名字旁有绿色喇叭；语音音量在设置中调整。
- ✅ **环境：** 通过头部之间的方块做射线检测（并在上方、两侧和脚边做平行射线）：每种材料以自己的方式透声和削弱高频（石头 30%，羊毛 16%，玻璃 55%，树叶 85%；台阶、门和栅栏部分阻挡；水和岩浆也会）；回声取决于说话者所在的空间（室外几乎没有，大厅和大洞穴更多）；水下说话者声音发闷；每个维度单独听。
