bridge-mind 追求功能完整，VoxelCraft 追求精简和性能。

## 一、生成 → 处理 → 渲染管线对比

| 阶段 | **old.htm（青屿）** | **VoxelCraft.html** | **bridge-mind.html** |
|---|---|---|---|
| 体量 / 依赖 | 1406 行，Three r170 ESM + Tweakpane，分 8 个 `<script type=module>`，通过 `gg` 全局对象协作 | 2590 行，Three r160 ESM，单个 module | 4464 行，Three r128 UMD + JSZip，19 个模块并有目录 |
| 世界表示 | **没有体素数据**，只有一个连续函数 `gg.height(x,z)` | `Uint8Array` 16×16×96，每格只存 blockId | 16×16×128，存 blocks、meta、sky、blk 四个数组，另有 biomes 和 tile entity |
| 噪声 | 7 个八度的 FBM 加一层山脊混合，参数全部能实时调 | 大陆、丘陵、山地遮罩和山脊叠加，加两组 3D 噪声挖面条洞穴 | 大陆、侵蚀、丘陵、山脊、温度、湿度，分 **9 种生物群系**，加 3D 洞穴、2D 峡谷、矿脉，地表物有区分 |
| 地物装饰 | 没有 | 树、草、花、4 种矿 | 3 种树、仙人掌、雪、冰、沙岩、结构钩子，玩家修改会保留（pending 修改） |
| 分块 | 64×64 平面，24 段细分，`PlaneGeometry` 逐顶点采样高度 | 16² 分块，螺旋顺序加载，要求 3×3 邻块都已生成 | 16² 分块，**三圈状态机**：RD+2 生成 → RD+1 光照 → RD 建网格 |
| 调度 | 每帧 10ms 预算，**朝视线方向多预取**（前方额外 4 圈，按 8 个朝向扇区排序） | 每帧 5ms 预算，用 urgent 集合优先重建被编辑的块 | 每帧 6ms 预算，分生成、光照、网格三个队列，各自按距离排序 |
| 光照 | 没有体素光照。用平行光（太阳、月亮）加半球光；DDA 模式下在 shader 里沿太阳方向发射线算阴影 | **每次建网格时重新算一遍** 48×48×96 区域的天光和方块光 BFS，再把中心块写回；边界变了就把邻块标脏 | **增量光照**：环形队列做 BFS，熄灯时先清除再从边缘重新传播，并且跨块 seed |
| 网格化 | 平滑模式：`toNonIndexed` 加 flat shading，按高度上色。体素模式：先把三角形重心光栅化成高度格，再按格生成顶面和外露侧面 | 逐面剔除，**不合并面**。顶点 AO 加 4 角平滑光照，并按 AO 选择四边形对角线方向 | **Greedy 合并**：只有贴图、着色、4 个角的光照和 AO 全部相同才合并。非立方体模型（门、火把、红石、作物、液体等）单独生成 |
| 顶点格式 | Float32 的 pos、normal、color | **非常紧凑**：pos 用 `Int16`（定点 ×64），uv 用 `Uint8×2`，data 用 `Uint8×4`（层、天光、方块光、shade）。上传 GPU 后释放 CPU 侧数组 | Float32 的 pos、uv、tile、light×2、tint×3，体积约是 VoxelCraft 的 3–4 倍 |
| 贴图 | 没有贴图；DDA shader 里用 hash 程序化生成 16px 方块纹理 | 程序化绘制后放进 **`DataArrayTexture`**（WebGL2 纹理数组，不会有图集渗色） | 程序化 Pix 绘制放进 2D 图集，用 `fract` 平铺并收缩 UV 防渗色；**可以加载 MC 资源包 zip**（含动画帧和生物群系着色） |
| 着色器 | 3 套可切换：①标准 PBR 平滑 ②线框 ③体素化网格；**④ 全屏 Max-Mip 四叉树 DDA 光线步进**（高度图转成 RT，再生成 6 级 max mip，含阴影射线、Veloren 式 AO、菲涅耳水面、焦散、泡沫、两段雾，支持低分辨率合成） | 自定义 Shader：取纹理数组，天光和方块光取最大值，再乘 AO 和雾 | 自定义 Shader，接入 Three 自带雾：天光 × 昼夜亮度、方块光、夜间色调、群系 tint |
| 透明 / 水 | 一个跟随玩家的大水面平面（DDA 模式下改为 shader 渲染水） | 水单独一个 mesh，顶部下沉 1/8，uWave 做 UV 流动 | 水单独一个 mesh；液体模型有流动高度 |
| 天空 | 渐变球加 hash 星星，雾颜色跟随地平线色，水下切换成水下雾 | 渐变球、太阳/月亮面片、900 颗星的 Points、环面映射的可平铺云 | 渐变球、日月、星星、**天气（雨/雪粒子）** |
| 生物 | 4 类生态 boid：鹿、蟹、鸥、鳐。SoA 存储，地面/空中**两套空间哈希**，状态机（觅食/休息/逃跑/顺风），群聚有对齐和聚合，**只在视野内生成，出视野就删除** | zombie、creeper、pig，有视线检测、白天燃烧 | 7 种生物，包括远程骷髅、苦力怕爆炸、羊毛颜色权重，AI 以 20Hz tick 运行 |
| 模拟 | 只有生物模拟 | TNT、掉落物、粒子、营养度（饥饿） | 20Hz tick：流体、随机 tick、耕种、火、下落方块、**红石**、熔炉、刷怪笼 |
| 持久化 | 没有（参数可以通过 `copy(JSON.stringify(gg.P))` 手动导出） | localStorage，只存修改差异（edits Map） | localStorage 用 **JSZip deflate 后 base64**，只存修改过的块并做 RLE；支持导出导入 JSON；关闭页面时同步保存 |

## 三、优势评估

**old.htm：图形研究和调参工具**
- 强项：**Max-Mip 分层 DDA 光线步进**是三者里技术含量最高的渲染。一张高度图 RT 就能覆盖约 2km 可视半径，自带阴影、AO、物理感水面，**远景几乎不随距离增加成本**。参数全部实时可调，适合原型设计。视线预取、生态 boid 加双哈希的设计都很精巧。
- 弱点：本质上是 2.5D 高度场，**不可能有洞穴、悬垂或可编辑方块**。物理只是钳高度。代码拼接痕迹明显：脚本之间靠 `gg` 隐式耦合，有"废弃"面板，`build` 对象被覆盖了两次，HTML 正文里还混着一行 `// ===== voxel.js` 文本。DDA 模式（wire=2）只是替换渲染路径，不改数据。

**VoxelCraft：最小可玩的 MC，性能取向**
- 强项：**顶点格式最紧凑**（Int16/Uint8，上传后释放 CPU 数组）。`DataArrayTexture` 彻底避免图集渗色。AO 对角线翻转、光照平滑都做得规范。手感和音效完成度高，单文件很容易读懂。
- 弱点：**每次重建网格都重算 3×3 区域的全量光照**，放一个火把就是一次 48×48×96 的 BFS，编辑频繁时会卡顿。没有 greedy 合并，所以 draw 的顶点数偏多。高度只有 96，内容也较少。

**bridge-mind：功能最全，工程化最好**
- 强项：生成、光照、网格三阶段状态机加邻块依赖，**跨块光照正确**。**增量光照（含熄灯处理）**是真正 MC 级的算法。Greedy 网格配合严格的合并条件，既减少面数又不破坏 AO。生物群系、红石、流体、资源包、压缩存档都有，所有系统挂在全局方便调试，STUB 索引也清楚。
- 弱点：Float32 顶点体积较大，r128 UMD 已经过时，没有声音也没有触屏。生成和网格都在主线程跑（三者都一样，都没用 Worker），视距调大时 6ms 的预算会成为瓶颈。
