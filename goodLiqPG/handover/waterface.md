# 水面 · 俯视着色 / Fresnel 与折射"镜头" / 水下看水面

> 对应文件：几何 `src/world/mesher.js:267–334`（`meshFluid`），着色 `src/render/shaders/water.js`，水下介质 `src/render/shaders/post.js`（体积光 `uw` 分支、composite、final），开关 `settings.waterStyle`。本文的行号和数值都按当前代码逐行核对过；§5 的"黑圈"成因是读码推导，未逐像素抓帧验证，下文分别标明。

## 1. 几何（mesher.js:267–334）

| 项 | 规则 |
|---|---|
| 格子高度 | `ownHeight`：源头 8/9；流动 `(8 − level)/9`；下落（meta&8）8/9；含水植物按 8/9；上方同种流体则为 1 |
| 角点高度 | 移植 `LiquidBlockRenderer.calculateAverageHeight`：取 4 格，高度 ≥ 0.8 的权重 ×10；任一邻格上方有水 → 1 |
| 顶面 | 只在上方不是同种流体时出；y = 角高 − 0.001；静水用 `water_still`，有坡度用 `water_flow` 并按 `atan2(fz, fx) − π/2` 旋转 uv（uv 基点 +1.5，靠 REPEAT 寻址） |
| 背面副本 | :311，同一组顶点、反绕序、法线取反；给水下看水面用 |
| 侧面 | 邻格不是同种流体且不是不透明方块才出；上沿取两角高度；`water_flow` 只取上半张（v ∈ 0…0.5）；**水的侧面也有背面副本**（:331） |
| 光照 | 取本格与相邻格（顶面取上方格）的较大天空光 / 方块光，不做 AO |
| tint | 群系水色，5×5 列平均（`colWater`） |

## 2. 顶点波（water.js:21–24）

```
Δy = 0.025 · (0.5·sin(0.7·x + 1.6·t) + 0.5·sin(0.9·z + 1.3·t)) − 0.03        x、z 取 mod 512 的世界坐标，t 单位秒
   ∈ [−0.055, −0.005]（单位：格）
```

只作用在正面顶面。背面副本停在 `h − 0.001` 不动，所以做顶点波时（Shader 风格，或相机在水下）**正面永远比背面副本低 0.004–0.054 格**；Classic 风格在水上不做顶点波，两者共面，同样会互相覆盖：

- 从上往下看：背面副本更近，曾抢先通过深度测试，走了水下分支，把水面画成近黑色。现在由 :144 `if (u_underwater < 0.5 && !gl_FrontFacing) discard;` 修复；原版模式下改为水上开启背面剔除（renderer.js:237–238）。
- 从下往上看：正面（低、带波）更近，可见的总是它，此时 `gl_FrontFacing = false`、`Ng = +Y` ⇒ `top = true`、`fromBelow = true`。这一点决定了 §5 用的是哪条法线。

## 3. 水面法线（water.js:58–73, 145–165）

波高场 `waveH(p, t)`（p = 世界 xz，单位格）：

| 项 | 方向 / 频率 | 振幅 | 时间速度 |
|---|---|---|---|
| 正弦 1 | `dot(p, (0.82, 0.57))·1.35` | 0.22 | 1.9 |
| 正弦 2 | `dot(p, (−0.43, 0.90))·2.10` | 0.14 | 2.4 |
| 正弦 3 | `dot(p, (0.97, −0.24))·3.30` | 0.08 | 3.1 |
| 值噪声 1 | `p·1.7`，平移 `(0.6t, 0.35t)` | 0.30（去中心） | – |
| 值噪声 2 | `p·4.1`，平移 `−(0.9t, −0.5t)` | 0.12 | – |
| 值噪声 3 | `p·9.0`，平移 `(1.3t, 1.1t)` | 0.05 | – |

- 法线：前向差分 `e = 0.05`，`N = normalize(−∂h/∂x·s, 1, −∂h/∂z·s)`。
- 强度 `s = mix(0.25, 0.55, wind)`；**水下乘 0.6**（:150）。风从天气来：晴 0.25 → s 0.325，雷暴 1.0 → s 0.55。
- 距离淡化：`N = mix(N, +Y, smoothstep(30, 140, d)·0.7)`，远处最多保留 30% 波动，避免闪烁。
- 雨涟漪（:156–163）：0.5 格网格，每格随机相位与中心偏移（±0.2），环 `sin((r − 0.6·ph)·40)`，半径 0.35 内有效，幅度 `0.8·wetness·smoothstep(0.8, 1, skyL)`（只在露天）。
- 水下 `N = −N`（:164）。

## 4. 俯视（从水面上方看，Shader 风格）

### 4.1 Fresnel（:169）

Schlick，F0 = 0.02（水的折射率约 1.33），用的是**波法线**与视线的夹角：

| 视线与法线夹角 | 0° 正俯视 | 45° | 60° | 70° | 75° | 80° | 85° | 89° |
|---|---|---|---|---|---|---|---|---|
| F | 0.020 | 0.022 | 0.051 | 0.141 | 0.239 | 0.398 | 0.641 | 0.917 |

所以正俯视几乎全是折射（看到水底，颜色由吸收决定），平视远处几乎全是反射。最终 `col = mix(refracted, refl, F) + min(sun, 60)`（:250）。

### 4.2 折射"镜头"（:171–178）

| 参数 | 值 | 作用 |
|---|---|---|
| 屏幕偏移 | `N.xz · 0.06 / max(1, 0.15·waterLin)`；侧面 ×0.3 | 近处偏移最大，约 6.7 格以外按距离反比缩小，远处不会撕裂 |
| 越界保护 | 偏移后的采样点比水面还近（`linDepth(rD) < waterLin`）→ 退回不偏移 | 防止把水面前方的物体（岸、手）折射进水里 |
| 厚度 | `thick = linDepth(场景) − linDepth(水面)`（视空间 z 差，不是射线长度）；身后是天空记 60 | 吸收按 z 差算，斜视时偏薄 |
| 源图 | `sceneCopy` = 水体绘制前的不透明场景（含天空，不含云、体积光、其他水面） | |

### 4.3 吸收与内散射（:180–189）

```
absorb      = (0.45, 0.075, 0.035) × 1.2 = (0.54, 0.09, 0.042) / 格
T           = exp(−absorb · thick)
waterAlbedo = srgbToLinear(群系水色) × (0.55, 0.85, 1.0)
scatterLight= (lightColor · max(L.y, 0) · 0.6 · sunVis + skyAmbient(+Y) · 0.9) · skyL² + torch · blkL⁴
inscatter   = waterAlbedo · scatterLight · 0.18
refracted   = behind · T + inscatter · (1 − T)
```

| 水深（格） | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|
| T (R, G, B) | .58 .91 .96 | .34 .84 .92 | .12 .70 .85 | .01 .49 .72 | .00 .24 .51 |

红光 4 格就基本被吃掉，所以浅滩发青绿、深海发蓝；这是参考图 gl2"透过水看到沙底"效果的来源。`sunVis` 是水面点的阴影查询（阴影图范围外用天空光近似）。

### 4.4 反射（:228–238）

| 参数 | 值 |
|---|---|
| 反射向量下折 | 顶面 `R.y < 0` 时 `R.y = −0.3·R.y`（陡浪法线不会反射出地平线以下） |
| SSR 步数 | 按画质：low 0（不做 SSR）/ medium 16 / high 24 / ultra 40（pipeline.js:12–15） |
| SSR 步长 | 首步 0.6 格，每步 ×1.22，抖动 `×(1 + 0.5·IGN)`；起点沿法线抬 0.05 |
| 命中判定 | 射线在场景之后且差值 < `2.5·step + 0.5`，且不是天空像素；再二分细化 5 次 |
| 屏幕边缘淡出 | `smoothstep(0, 0.08)` × `smoothstep(1, 0.92)`（u、v 两向） |
| 未命中 | 天空 LUT（y 截到 ≥0）× `skyOcc = smoothstep(0.5, 1.0, skyL)`；洞穴、屋檐下不反射天空 |
| 局限 | SSR 取的是 `sceneCopy`：**反射里没有体积云**，天空部分只有 LUT 渐变 |

### 4.5 太阳高光（:240–248）

GGX，`α = 0.012`（`D_GGX` 内部再平方，非常尖），Smith 可见项，Fresnel 用 `F_Schlick(0.02, H·V)`，乘水面点阴影（范围外用 `skyOcc`），截断到 60。配合波法线，低太阳角时会形成参考图 gl1 那种一路延伸到太阳的碎金光带。

### 4.6 Classic 风格（:204–226，Video Settings → Water: Classic）

平面法线（不做波和涟漪）；原版 `water_still` / `water_flow` 动画贴图 × 群系色，用阴影 + 天空环境光 + 火把光照亮；按贴图 alpha 盖在**不折射**的场景上（原版观感）；天空反射 `mix(…, sky, F·0.6)`；太阳高光 GGX α = 0.05、×0.02、截断到 20。水下不受这个开关影响。

## 5. 水下看水面（fromBelow 分支，water.js:191–202）

```glsl
float tir   = smoothstep(0.62, 0.70, 1.0 - max(dot(V, vec3(0.0, -1.0, 0.0)), 0.0));  // :194
vec3 abovee = texture(u_sceneColor, scr + N.xz * 0.04).rgb;                          // :195
if (texture(u_sceneDepth, scr + N.xz * 0.04).r >= 0.99999)
    abovee = sampleSkyLUT(u_skyLUT, normalize(refract(-V, N, 1.33)));               // :196
vec3 deep   = u_waterFogColor * 0.4;                                                 // :197
vec3 col    = mix(abovee * 0.9, deep, tir);                                          // :198
```

逐项说明：

| 项 | 实际含义 | 数值 |
|---|---|---|
| `V` | 从水面像素指向相机，水下仰视时向下 | – |
| `1 − dot(V, −Y)` | `1 − cos θ`，θ = 视线相对竖直方向的天顶角 | – |
| **窗口边缘** | `tir = 0` 到 θ = **67.7°**，`tir = 1` 从 θ = **72.5°** 起 | 物理 Snell 窗口半角 = arcsin(1/1.33) = **48.75°**（`1 − cos θc = 0.341`） |
| 窗口形状 | `tir` 只用视线几何，不用波法线 → 圆形、以竖直方向为中心（跟世界走，不跟镜头走）、边缘无波动 | – |
| 窗口外 | `deep = u_waterFogColor × 0.4`；`u_waterFogColor = env.waterFogLinear \|\| (0.02, 0.06, 0.10)`（pipeline.js:289），而 `env.waterFogLinear` **从未赋值** | 恒为线性 (0.008, 0.024, 0.040)，与群系、时间、深度都无关 |
| 窗口内扰动 | 屏幕偏移 `N.xz × 0.04`，`N` = 取反后的波法线（强度 ×0.6、距离淡化、雨涟漪都在内）；偏移不随距离缩放 | – |
| 窗口内亮度 | `abovee × 0.9` | – |
| 未用变量 | `:193 float cosT = dot(-N, V);` 算了没用 | – |

### 5.1 "黑圈"的成因（用户反馈：水面方向的圆形 FoV 裁剪太广，像个黑圈）

1. **窗口太宽**：透明窗口一直开到 67.7°–72.5°，物理上 48.75° 之外就该是全反射。窗口外直接填常量 `deep`（线性 0.008, 0.024, 0.040），在水下自动曝光后接近黑色 ⇒ 视野外围一圈暗环，圆心在头顶正上方。
2. **48.75°–67.7° 之间、且水面上方是天空的像素**（推导，未抓帧验证）：`refract(-V, N, 1.33)` 在超过临界角时返回 `vec3(0)`，`normalize(vec3(0))` 得 NaN，`sampleSkyLUT` 的 `atan` / `asin` 再传播 NaN，纹理采样结果未定义，多数驱动表现为黑色或错色。这一圈有波法线参与，边缘会抖。上方是地形时走的是 `sceneColor` 采样，不受此影响，但同样把本该全反射的区域画成了岸上的景物。
3. 两者叠加：内侧一圈（2）可能发黑、闪烁，外侧（1）恒定近黑。

修正方向（未改动代码，供接手者参考）：

- 窗口边缘改成物理值：`tir = smoothstep(0.30, 0.36, 1 − cosθ)`；或者用 `k = 1 − η²(1 − (N·I)²)`，`k < 0` 即全反射，这样边缘会跟着波浪起伏。
- `refract` 结果为零向量时不要 `normalize`，直接走全反射分支。
- 窗口外不要填常量：用 `reflect(-V, N)` 的方向取水下场景（再做一次屏幕空间追踪，或用水体雾色乘天空光近似），并给 `env.waterFogLinear` 按群系 `waterFogColor` 与相机天空光赋值（environment.js:185–189 已经算出了原版水下雾色，可以转线性后复用）。

## 7. 风格开关与验证记录

- `settings.waterStyle`：`'shader'`（默认）/ `'classic'`，在 Video Settings 的 "Water" 按钮切换并持久化；`renderer.setShaderMode(…, waterStyle)` → `pipeline.waterStyle` → uniform `u_waterStyle`（VS、FS 都有）。
- 验证（seed 12345，海洋 (−288, 949)）：
  - 水下同一机位，两种风格截图逐像素平均差约 4/255，只是动画和 TAA 噪声 ⇒ 水下确实一致；
  - 水上两种风格都正常：Shader 有波浪、反射和折射，Classic 是原版半透明贴图；
  - 修复前从上方看两种风格都几乎全黑，原因见 §2。
